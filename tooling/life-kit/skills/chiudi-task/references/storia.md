# Close task — incident history

Why the procedure has its rules. `SKILL.md` contains the rule; this file contains the facts.

- **Fixed-name report (until 2026-09-21)**: `.claude/chiusura.md` was guaranteed to cause collisions. Worktree isolation is the first step in every session, so two sessions closing tasks on the same day wrote to the same path; whoever merges resolves the content conflict in a non-code file by keeping one report and discarding the other. On the issue portal, two reports from 2026-09-17 conflicted four days later. Hence one file per task: `.claude/chiusure/YYYY-MM-DD-<slug>.md`.
- **Phantom nodes in the brain**: inside a worktree, `--show-toplevel` returns the task name, not the project name. Six phantom nodes appeared in the issue portal. Hence the slug is derived from the main checkout root (`--git-common-dir`).
- **Report label**: any `#N` found in the text can also refer to issues the task does not close. Hence `Closes #N` in the report or commits; otherwise use the filename slug.
- **Brain index not regenerated (observed 2026-09-16)**: the Stop hook `suite-wiki-sync.sh` regenerates the node the session is working on, but the note lands in another tree's brain. 20 notes orphaned from the index, all and only `nodes/*/closures/*.md`. The person depositing the note is the only one who knows to regenerate it.
- **Deposit as prose, skipped (2026-09-14)**: the brain contained 39 reports, 4 committed; the other 35 existed only on one machine's disk, one `git clean` away from disappearing. Copying without versioning creates an archive that lies about how long it will last. Hence this step is code (`chiudi.py`).
- **Exit 3 treated as success**: the suspended `done` gate responds with 200 because the request succeeded; treating that as success printed “closed” and `/exit`, losing the session over a gate that one commit would have cleared.
- **Task completion marker**: SessionEnd alone means “the window closed,” and a window also closes when VS Code restarts. Hence the `state/fine-task/` marker, written by `chiudi.py` before it contacts the Launcher.
- **Nodes deposited into the wrong tree's brain (issue #51, 2026-10-26)**: when a node bucket has multiple sibling trees and the `suite_core` resolver does not respond, `chiudi.py` fell back to `PATH_LIFE_BRAIN`, which can point to a different tree (for example, `~/work` for a node in `~/personal`). Hence, in an ambiguous case, choose the tree where the node is registered (graph or roster); if no choice can be made, do not deposit — never fall back to `PATH_LIFE_BRAIN`.
