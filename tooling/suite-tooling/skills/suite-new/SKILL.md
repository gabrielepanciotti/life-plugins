# /suite-new — create a new Life node

Create a standalone node that follows the fractal standard, starting from a minimal identity.

```
cd packages/shared
.venv/Scripts/python -m suite_core.nodes new "<DisplayName>" "<slug>" "<Cluster>" --type <type> --dest "<path>"
```

- `<DisplayName>` PascalCase (e.g. `RentFinder`) · `<slug>` stable **camelCase** id (e.g. `rentFinder`)
- `<Cluster>` must name a cluster in the Life graph (for example, Home, Learn,
  Travel, Finance, Work, or System) · `<type>` ∈
  fastapi-react-app/fastapi-app/react-app/bridge/cli/leaf
- `<path>` = folder for the new repo, **named after `<DisplayName>`** (e.g. `$SRV_ROOT/RentFinder`).
  Enforced taxonomy (Life#114): a non-camelCase slug or a folder with a different name
  is rejected before writing; the GitHub repo is also named `<DisplayName>`.

Runs in order: per-type scaffold → register in `life.graph.json` + regenerate ports → `git init`+commit
→ `conform` → venv 3.13 + install → `link`. Prints status by phase (`ok`/`skipped`/`error`).
Idempotence/safety: fail-fast validation before writing; if a late phase fails, the node
remains created and registered (no rollback). See `docs/onboarding/node-realignment.md`.

> **Partial failure**: on any phase `error`, check `git status` in `$SRV_ROOT/Life` for a stray
> `life.graph.json`/ports edit, and check the new node's dir for partially written files.

## Canonical backend layout

The scaffold generates the backend as a **package** `backend/<pkg>/` (`<pkg> =
slug` in snake_case + `_backend`, e.g. `callManager` → `call_manager_backend`) with `app.py` (`create_app()` → `/health`) and
`__main__.py` (port from env `PORT`). Run it with `python -m <pkg>`; requirements
are in **`backend/requirements.txt`**. The **`deploy/`** folder is generated by
conform (suite-managed) — do not edit it manually.

## Instance specifics

Run `python -m suite_core.nodes skill-overlay suite-new` and apply what it prints (it may print nothing).
