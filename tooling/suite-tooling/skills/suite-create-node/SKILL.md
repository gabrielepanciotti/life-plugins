# Create a Life node

Scaffold a new fractal node and register it in its parent.

1. Identify the PARENT node directory (the dir containing the parent `node.config`),
   the new node `Name` (capitalized, English, generic), its `slug` (camelCase, Life#114),
   and optionally its `type` (e.g. `fastapi-react-app`, `bridge`, `leaf`).
2. From `Life/packages/shared`, run:
   ```bash
   .venv/Scripts/python -m suite_core.nodes create <parent-dir> <Name> <slug> [--type TYPE]
   ```
3. Then resolve the new node to materialize its config:
   ```bash
   .venv/Scripts/python -m suite_core.nodes resolve <parent-dir>/children/<Name>
   ```
4. Report the created path and the resolved type/capabilities. The node inherits
   tooling from its ancestors automatically (see [[suite-resolve-node]]).

## Canonical backend layout (anchored to `life_backend`)

The skeleton generates the backend as a **Python package**, not a single module:

- Code in **`backend/<pkg>/`** where `<pkg> = slug.replace('-','_') + '_backend'`
  (e.g. slug `hub-offerte` → `hub_offerte_backend`).
- The package has `__init__.py`, `app.py` (exposes `app` — by default
  `from suite_backend_core import create_app; app = create_app()`, which already provides
  `/health`) and `__main__.py` (starts uvicorn, **port read from env `PORT`**).
- Run with: `python -m <pkg>`. Requirements are in **`backend/requirements.txt`** (as in
  `life_backend`), not in the root.
- The folder **`deploy/`** is generated by **conform** (suite-managed: Dockerfile,
  compose, Caddyfile, `*.Dockerfile.dockerignore`) — do not edit it manually.

## Brain wiki and visibility

Conform automatically scaffolds the **`brain-wiki`** asset in the new node:
- The `brain/` folder with domain subfolders (`overview`, `architecture`,
  `concepts`, `decisions`, `glossary`, `gotcha`, `runbook` + extra domains for
  the node's `type`) each containing `_README.md`.
- `brain/private/` — always present, gitignored.
- `brain/index.md` and `brain/CHANGELOG.md` — regenerated by `wiki-sync`.

**Private business node**: add `"visibility": "private"` to `node.config`
before running conform. This makes the **entire** `brain/`
gitignored (not just `brain/private/`), indexes every chunk as
`private`, and ensures the gate never publishes it.

```json
{
  "schemaVersion": "2.0",
  "name": "Hub Offerte",
  "slug": "hub-offerte",
  "type": "cli",
  "visibility": "private",
  "inherits": "../node.config"
}
```

`visibility` is inheritable (nearest wins along the `inherits`): a
business subtree can inherit `private` from its parent without redeclaring it
in every child; a child can force `public` again if needed.

## Instance specifics

Run `python -m suite_core.nodes skill-overlay suite-create-node` and apply what it prints (it may print nothing).
